# CTRL 26 皮肤项目详解

本文档面向想要了解、学习或魔改 CTRL 皮肤的开发者，系统性地说明仓库中每个部分的作用、文件格式、以及它们如何组合成一套完整的 FM26（Football Manager 26）皮肤。

---

## 1. 项目简介

**CTRL 26** 是由 MW90（GitHub: matt-wadsworth）开发的 FM26 自定义皮肤，当前版本 1.8（2026-06-10，适配 FM 26.3.2 更新）。

与 FM24 及更早版本的"XML 皮肤"体系不同，**FM26 基于 Unity 引擎 + Unity UI Toolkit（UXML/USS）构建**，UI 全部打包在 Asset Bundle（`.bundle`）文件中。因此本项目本质上是一个"源文件仓库"：存放 USS（类 CSS 样式）、UXML（UI 结构）、JSON（布局/表格）、PNG（图标/贴图）、字体等源资源，再通过外部工具 **FM Skin Builder** 构建（编译/替换进 bundle）并应用到游戏。

皮肤的视觉基调：深午夜蓝背景（`#050d1c` / `#121a24`）+ 黄色高亮（`#fbc500`）+ 浅灰白文字（`#d9e8ed`），整体扁平、去边框、低饱和。

### 仓库基本信息

| 项 | 内容 |
| --- | --- |
| 仓库 | `https://github.com/SilasFan/ctrl-fm-capa`（分支 `main`） |
| 皮肤名 | CTRL（见 `config.json`） |
| 版本记录 | `CHANGELOG.md`（1.0 于 2026-02-20 发布，最新 1.8 于 2026-06-10） |
| 构建工具 | [FM Skin Builder](https://fmskinbuilder.com)（必需） |
| 深度修改工具 | UABEA（Unity Asset Bundle Extractor Advanced，手工补丁用） |
| 发行渠道 | FM Skin Builder 皮肤库 / 官网 [CTRL 26 页面](https://fmskinbuilder.com/skins/ctrl-26) |

### 使用许可（README 要求）

仓库公开的目的是供个人学习、魔改自用。**不要**对 CTRL 做少量修改后就以自己的名义发布；公开发布的作品应当是有实质原创内容的成果。

## 2. 技术背景：FM26 皮肤的分层结构

理解本项目需要先了解 FM26 皮肤的三个修改层次，从浅到深：

```
┌─────────────────────────────────────────────────────────┐
│ 第 1 层：资源覆盖（styles/ fonts/ graphics/ 等）           │
│  · USS 样式表 → 替换游戏内的 AlwaysAppliedStyleSheet 等   │
│  · UXML 面板  → 按文件名覆盖游戏内同名面板模板             │
│  · JSON 布局  → 替换首页/报表的卡片网格与表格列定义         │
│  · PNG/字体   → 按 mapping.json 映射替换游戏内贴图与字体    │
│  → 全部由 FM Skin Builder 在构建时自动注入 bundle          │
├─────────────────────────────────────────────────────────┤
│ 第 2 层：贴图补丁（_uabea/backgrounds/）                   │
│  · 以 BC7 纹理格式直接替换 bundle 中的背景贴图              │
│  · 由 patch.json 清单描述，构建工具可自动应用               │
├─────────────────────────────────────────────────────────┤
│ 第 3 层：序列化资产手术（_uabea/ 其余补丁目录）              │
│  · 直接编辑 bundle 内 USS/UXML 的序列化 JSON 转储           │
│  · 涉及 references 表、绑定(Binding)、池化数值等底层结构     │
│  · README 注明部分改动需要在 UABEA 中手工完成               │
└─────────────────────────────────────────────────────────┘
```

- **第 1 层**是日常皮肤开发的主要方式，改起来最安全、最直观。
- **第 2、3 层**用于处理"文件覆盖做不到"的改动，例如：主界面背景贴图替换、消息未读指示器样式、报告页渐变、替补席卡片、战术页头像等——这些内容被序列化进了 bundle 内部，必须改 bundle 本身。

游戏安装目录（Windows Steam 版，bundle 最终落点）：
`C:\Program Files (x86)\Steam\steamapps\common\Football Manager 26\fm_Data\StreamingAssets\aa\StandaloneWindows64`

## 4. 根目录文件

### 4.1 `config.json` — 皮肤清单

FM Skin Builder 读取的入口文件，声明皮肤名称与参与构建的资源目录：

```json
{
  "schema_version": 1,
  "name": "CTRL",
  "description": "CTRL is a custom skin for FM26 by MW90.",
  "includes": [
    "graphics/icons/condition", "graphics/icons/misc",
    "graphics/icons/preferences", "graphics/icons/stars",
    "graphics/icons/union", "graphics/mainmenu",
    "graphics/icons/morale", "graphics/icons/sharpness",
    "graphics/icons/status", "graphics/news",
    "styles", "fonts", "graphics/pitch",
    "graphics/icons/fatigue", "panels",
    "table-views", "tile-layouts", "graphics/match"
  ]
}
```

注意：`includes` 中列出了 `graphics/pitch`，但仓库中该目录并不存在（历史遗留的可选包含项），不影响构建。

### 4.2 `README.md`

包含：使用许可说明、通过 FM Skin Builder 安装/下载的指引、从源码构建的四个步骤（打开文件夹 → Build → 等待输出到 `packages/` → Apply to Game）、以及一条重要提示——**部分改动（消息指示器、渐变、替补席卡片等）必须在 UABEA 中手工应用，详见 `_uabea/UABEA-Notes.md`**。

### 4.3 `CHANGELOG.md`

按版本记录所有变更，条目按 Fixed / Added / Changed 分类，并标注对应的游戏更新（如 26.2、26.3.1 国际管理模式更新、26.3.2）。研究"某个功能是怎么来的"时非常有用，例如 1.3 版把比分板移到了屏幕左侧、1.7 版加入了自定义比分板和国家队支持、1.8 版全面加入背景图。

### 4.4 `.gitignore`

忽略的都是构建/发行产物：`/packages`（FM Skin Builder 构建输出）、`/_releases`、`/dist`、`/media`、`.prettierrc`。

## 5. `styles/` — USS 样式表（皮肤的核心）

FM26 的 UI Toolkit 使用 **USS**，语法与 CSS 几乎一致（支持 `:hover`、`var()` 自定义属性等，但选择器能力受限，且有 `-unity-` 前缀的专有属性）。本目录共 9 个文件约 2000 行，通过 `mapping.json` 注入游戏内对应的样式表资产：

```json
{
  "variables.css": "AlwaysAppliedStyleSheet",
  "misc.css":      "AlwaysAppliedStyleSheet",
  "tiles.css":     "AlwaysAppliedStyleSheet",
  "inputs.css":    "AlwaysAppliedStyleSheet",
  "header.css":    "AlwaysAppliedStyleSheet",
  "text.css":      "AlwaysAppliedStyleSheet",
  "fixes.css":     ["AlwaysAppliedStyleSheet", "iPhoneStyles"],
  "_testing.css":  "AlwaysAppliedStyleSheet",
  "match.css":     ["AlwaysAppliedStyleSheet", "MatchUIStyles"]
}
```

映射机制：键为本地文件名，值为**游戏内 USS 资产名**。`AlwaysAppliedStyleSheet` 是全局生效的基础样式表；`MatchUIStyles` 只在比赛日界面加载（所以 `match.css` 同时注入两者）；`iPhoneStyles` 是小屏/特殊布局样式表（`fixes.css` 对其做修正）。

### 5.1 `variables.css`（89 行）— 设计令牌（Design Tokens）

在 `:root` 上定义全套 CSS 变量，是**整个皮肤配色的一站式开关**：

- **基础中性色**：黑 `#060d17`、白 `#d9e8ed`
- **Teal 绿**系（原本是青绿主题的残留，现多数已改深绿）
- **品牌色**：midnight 午夜蓝 `#050d1c` / `#121a24`、cloud 云白、horizon 亮黄 `#fbc500`（本皮肤的主高亮色，多个变量别名都指向它）、twilight 半透明白
- **Alpha 半透明白**梯度（8/12/14/16/20/35/65/75/85/90），用于悬停、边框、分隔线等
- **组件级变量**：Continue 按钮配色、表格行 hover/斑马纹/选中色、战术页激活态、SpeakTo 面板底色、次级按钮边框、合同谈判成功/失败/无效底色等

改主题色优先改这里（尤其是 `--colours-brand-foundation-horizon` 的黄色和各处硬编码的午夜蓝）。

### 5.2 `misc.css`（824 行）— 杂项覆盖

按注释分节，覆盖面最广：滚动条（隐藏）、球员报告、轮播（Carousel）、分隔线、照片/缩略图、消息（收件箱）、**数据表格单元格**（篇幅最大的一节，涉及属性色阶、状态色等）、日历、步进器、悬浮提示、折线图、**球员状态指示**（伤病/停赛等主题化）、SpeakTo 谈话面板、体测结果、会议、合同谈判气泡、启动画面/主菜单。

### 5.3 `tiles.css`（317 行）— 卡片/磁贴/弹窗

首页网格中的"磁贴（Tile）"是 FM26 界面的基本单元。本文件覆盖：磁贴基底（去边框、圆角、悬停效果）、战术类磁贴、卡片与弹窗、新闻磁贴、**球员属性大块**（属性数值配色）、轮播磁贴指示器、SpeakTo 侧栏、赛季前瞻，以及**背景图样式**（1.8 版为配合全屏背景图新增的遮罩/亮度处理）。

### 5.4 `inputs.css`（500 行）— 输入控件

下拉菜单（SI Dropdown）、导航标签、**单选按钮**、**开关（Switch）**、**复选框**的全面重绘，以及战术页、球员报告、球队界面中输入控件的场景化修正。CTRL 把这些原生控件改成了扁平、细边框、黄色激活态的风格。

### 5.5 `header.css`（148 行）— 顶部导航栏

主导航容器（加底色和 1px 分割线）、**移除俱乐部颜色渐变与队徽色条**（`titlebar-gradient-1` 宽度归零等，让顶栏保持皮肤自身配色）、Portal 入口图标/文字的默认与悬停着色、右上角功能按钮（统一 40px 圆角方块）、日历按钮、**Continue 按钮**（圆角胶囊、悬停变色、"Must Respond"红色脉冲态）、书签与未读红点、经理下拉框。

### 5.6 `match.css`（144 行）— 比赛日界面（仅 MatchUIStyles 加载时生效）

比赛顶部信息、**比赛控制按钮组**（播放控制，透明底+悬停亮起）、比赛引擎按钮/通知 toast、**替补席/球队概览面板**（Squad Overview，圆角描边卡片）、红牌块、底部区域留白（给解说条让位）、赛前阵容名单配色。

### 5.7 其余

- `text.css`（4 行）：极小的文字修正。
- `fixes.css`（20 行）：小修补，额外注入 iPhoneStyles。
- `_testing.css`（0 行）：空的试验场文件，仍挂在映射里。

## 6. `panels/` — UXML 面板覆盖（20 个文件）

UXML 是 Unity UI Toolkit 的界面结构文件（类 HTML，带数据绑定命名空间 `si:`/`fm:`）。**以游戏内同名资产为键覆盖**：文件名即要替换的面板/组件模板名。

本目录的文件反映了 CTRL 改动过的界面结构，代表性条目：

| 文件 | 覆盖的界面 |
| --- | --- |
| `OverviewPrototype.uxml` | 比赛日总览原型（排布替补席事件卡片 `Dugout_4x8_with_collapse`、VAR 提示、解说条 `MatchCommentary` 的组合容器） |
| `MatchCommentaryBar.uxml` | 比赛解说条（重排样式，配合 `match.css`） |
| `MatchStatsMomentumxGLatestScoreLiveTableCarousel_4x4.uxml` | 比赛统计/势头/xG/实时比分表格轮播磁贴 |
| `PortalMessagesTile.uxml` / `PortalIncomingMessagesTile.uxml` | 收件箱消息磁贴（1.3 版把原来需要 UABEA 的改动迁到了 UXML） |
| `MeetingSpeakToContainer.uxml` | 会议/谈话容器 |
| `ScoutedProsAndCons.uxml`、`CoachReportProsRow/ConsRow.uxml`、`data_display-string-list-item-pro-con.uxml` | 球探/教练报告的优缺点行（1.1 版新功能） |
| `PlayerAttributesLargeBlock.uxml` | 球员属性大块 |
| `TacticsPositionDetailed.uxml` | 战术位置详情 |
| `QuickStartTile_4x4.uxml`、`MainMenuStartNewCareerFIFAWorldCupTile_4x4.uxml`、`AdvanceSetupTile_4x4.uxml` | 主菜单开新档相关磁贴（1.7 版为国际管理/世界杯重新设计） |
| `InternationalFinalsBlock.uxml` | 国际大赛决赛板块 |
| `TrendingIndicator.uxml`、`FinancesReportLineChartPointSmall.uxml` | 趋势指示器、财务折线图数据点 |
| `PhotosensitivityWarning_SplashScreen.uxml` | 启动光敏警告页 |
| `dashboard-hud-search-button.uxml` | 顶栏搜索按钮 |

文件内容特征：保留原版的 `si:BindingRoot`/`BindingRemapper` 数据绑定结构（`binding="kind=1; path=match.IsInOverview"` 这类游戏数据路径），只重排视觉元素——所以魔改 UXML 时必须小心不要破坏绑定路径。

## 7. `tile-layouts/` — 卡片网格布局（23 个 JSON）

FM26 的球队首页、报告页由**磁贴网格（Composition）**组成。每个 JSON 定义一个界面的磁贴排布：

```json
{
  "name": "SquadComposition-Large",
  "grid": { "width": 20, "height": 10 },        // 网格规格 20×10
  "tiles": [
    {
      "tile": "SquadFirstTeamTile_8x8",          // 磁贴模板名
      "x": 0, "y": 0, "w": 8, "h": 10,          // 在网格中的位置与占格
      "isDynamic": true,                          // 是否动态内容
      "guid": "cb6226a4...",                     // 对应 UXML 资产的 GUID
      "path_id": "4009900239504513551"           // bundle 内的 Path ID
    },
    ...
  ]
}
```

布局清单（`-Large` 后缀为大屏变体）：

- **球队（Squad）**：`SquadComposition-Large`、`SquadInternationalManagerComposition-Large`、`SquadLoansCardPlayersOnLoanComposition`
- **球员报告**：`PlayerReportOverview/Performance/Career-...`、`PlayerReportPerformanceAIComposition`、`PlayerReportPerformanceLoanOutGridComposition`、`PlayerReportTooltipGridComposition`（悬浮卡）
- **俱乐部**：`ClubSiteComposition - Large`、`ClubSiteAIComposition - Large`、`ClubComposition-Large`、`ClubProfileInMatchCardGridComposition`
- **门户/收件箱**：`Portal-Large`、`InternationalPortalInCamp/InMajorCompetition-Large`
- **主菜单**：`MainMenuHasSaveComposition-Large`（及 `-IM` 国际管理变体）
- **其他**：`RecruitmentComposition-Large`（招募）、`MyHistoryCardGridComposition`（经理履历）、`MatchExperienceGridComposition-Large`、`OnThePitchComposition-Large`、`IndividualTrainingTileComposition-Large`（个人训练，1.1 版重做）

魔改方式很直白：调整 `x/y/w/h` 即可重排首页；引用游戏内已有磁贴模板（需正确的 guid/path_id，可从 UABEA 转储或原版布局中查到）。

## 8. `table-views/` — 表格列视图（2 个 JSON）

自定义数据表格的列集合（1.5 版加入，基于社区 sas/SYC 的表格方案）：

- `SearchResultsTableScoutPosition.json` — 搜索结果中的"球探-位置"视图
- `TransferRoomInAdvertResponsesTableScoutPosition.json` — 转会房间收到的求职/应聘回应表的同款视图

格式为 `columns[]`，每列声明 `columnID`（对应游戏内列类型，如 `recommendation-grade-only`、`knowledge`、`transfer-value`、`portrait-name`、`nation`、`international-caps`…）及 `widthOverride`/`minWidthOverride`/`required`/`sortingDisabled`。游戏内置列 ID 都可以这样自由组合。

## 9. `fonts/` — 字体替换

| 文件 | 替换的游戏内字体 |
| --- | --- |
| `BigShoulders-Bold.ttf` | `FMUniverse-Regular`、`GT-America-Standard-Black`（标题/显示字体） |
| `Nacelle-Regular.otf` | `NotoSans-Regular`、`ABCSocial-Regular`（正文/回退字体） |

`mapping.json` 的键是本地字体文件，值是要顶替的游戏内字体名列表——即 CTRL 用 Big Shoulders 做标题字、Nacelle 做正文字。想换字体只需替换 TTF/OTF 并保持映射（或改映射指向）。注意 CHANGELOG 1.1 提到"移除了对语言字体的替换"，即不再覆盖其他语种字体，避免非拉丁字符显示问题。

| 子目录 | 内容 | 数量 |
| --- | --- | --- |
| `icons/stars` | 星级评分图标（当前/潜力、半星、青年队变体，参数化映射） | 12 |
| `icons/morale` | 士气表情图标 | 19 |
| `icons/condition` | 体能状况 | 5 |
| `icons/sharpness` | 锐度/比赛状态 | 7 |
| `icons/fatigue` | 疲劳度（1.5 版新增） | 5 |
| `icons/status` | 状态图标 | 3 |
| `icons/union` | 属性升降箭头等联合图标 | 6 |
| `icons/preferences` | 设置页图标 | 8 |
| `icons/misc` | 杂项（齿轮、删除、编辑、警告、FM logo 等） | 12 |

## 11. `_uabea/` — UABEA 手工补丁（进阶核心）

**UABEA**（Unity Asset Bundle Extractor Advanced）可以直接导出/回导 bundle 内序列化资产。当改动涉及"序列化进 bundle 的 USS/UXML"（文件覆盖无法表达）或贴图格式级替换时，就需要这一层。本目录包含 16 个补丁，结构高度规范化：

```
_uabea/
├── UABEA-Notes.md          # 总索引 + 工作流程规范（见下）
├── backgrounds/            # 贴图补丁（唯一 type:texture 的）
│   ├── patch.json          #   机器可读清单
│   └── assets/             #   bg.png、mainmenu.png、startup.png
│                            #   comps/bg-{pl,ucl,bundesliga,wc,...}.png
└── <patch-slug>/           # 其余 15 个 USS/资产类补丁
    ├── patch.json          #   补丁清单（id/name/enabled/assets[]）
    ├── <NAME>_CHANGES.md   #   人工可读的变更说明（改了什么、目标值）
    ├── win/                #   Windows 平台的 JSON 转储
    │   ├── orig/           #     原始基线（绝不修改）
    │   └── *.json          #     修改后待回导的工作副本
    └── mac/                #   macOS 平台同构（ID 不同，不能互抄）
```

### 11.1 `UABEA-Notes.md` — 流程圣经

这是整个手工补丁体系的方法论文档，规定了：

- **基线纪律**：`win/orig`、`mac/orig` 存放原版导出，永不修改；工作副本放同级 `win/`、`mac/`。
- **`[n]` 记号**：补丁文档中的 `[n]` 一律指目标 JSON 数组的 **0 基下标**（如 `rule [2]` → `m_Rules.Array[2]`），不是行号也不是 Unity `rid`。
- **`references` 表**：每个资产的序列化引用表，`references.RefIds[n]` 取第 n 项；结构改动后必须校验 `rid`、`m_Id`、绑定、`uxmlAssetId`、`inlineSheet` 相互一致才能回导。
- **绑定包装**：`Binding.m_direct` 等字段在两个平台都要用 `Path + Nullable` 包装格式，不能留旧扁平格式。
- **AI 辅助流程**：大结构 diff 交给 AI 总结，但**目标字面值必须人工写入文档**，防止"孤儿转储"失传。
- **资产索引表**：bundle 名 + 资产文件名 + Path ID → 属于哪个补丁，用于在 UABEA 中快速重开资产。
- **Extras**：未正式化的实验（报告页渐变的 `m_SerializedData` rid 对调、球员头像缩放的池化数值调整）。

### 11.2 `backgrounds/` — 背景贴图补丁（1.8 版主打）

`patch.json` 声明 `"type": "texture"`、`"format": "BC7"` 的替换项：

- `bg.png` → 替换 `ui-backgrounds_assets_common` 中**全部 17 个室内场景背景**（董事会会议室/更衣室/采访区/发布会/会议室的各档次变体），实现"全游戏统一暗色背景"。
- `comps/bg-*.png` → 按赛事替换 licensed 联赛/杯会背景（英超、欧冠/女欧冠、欧联/欧协联、德甲、EFL 三级+联赛杯+附加赛、世界杯等，注意部分目标在 `ui-backgrounds_assets_` 与 `ui-backgrounds_assets_common` 两个 bundle 中各有一份）。
- `mainmenu.png` → 主菜单底图；`startup.png` → 启动动态纹理。

## 14. 常见魔改场景速查

| 想改什么 | 去哪里改 |
| --- | --- |
| 全局主题色/强调色 | `styles/variables.css`（黄色是 `--colours-brand-foundation-horizon`；午夜蓝散落在各文件的硬编码里） |
| 按钮/开关/下拉等控件外观 | `styles/inputs.css` |
| 顶栏、Continue 按钮、未读红点 | `styles/header.css` |
| 比赛日界面 | `styles/match.css` + `panels/Match*.uxml` + `_uabea/match-*` 补丁 |
| 首页/报告页磁贴排布 | `tile-layouts/*.json`（改 x/y/w/h） |
| 表格列 | `table-views/*.json`（columnID 组合） |
| 字体 | `fonts/`（同名替换 + mapping.json） |
| 星级/士气/体能等图标 | `graphics/icons/<类>/`（同名替换 PNG） |
| 新闻配图、赛前阵容/积分表图 | `graphics/news/`、`graphics/match/` |
| 全局/赛事背景图 | `_uabea/backgrounds/assets/`（需构建/UABEA 流程） |
| 深层结构（绑定、序列化样式） | `_uabea/<补丁>/`，先读 `UABEA-Notes.md` |
